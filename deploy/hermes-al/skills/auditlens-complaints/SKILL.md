# Жалобы клиентов в AuditLens

## Overview
Жалобы — отзывы клиентов со всех площадок (banki.ru, Сравни, Финуслуги и др.),
которые модель прочитала и разметила: продукт, **главная проблема** (код
кодификатора), признаки (эскалация, «без согласия», «ввели в заблуждение»),
пересказ и дословная цитата. Счётчики во вкладке «Отзывы», в «Обзоре» и в
инструментах `mcp__auditlens__complaint_*` считаются по этой разметке — числа
должны совпадать с тем, что видит аудитор.

## When to Use
- «Сколько жалоб», «на что жалуются», «что растёт», «сигнал дня», «почему всплеск».
- Жалобы по продукту («жалобы на вклады»), по банку, по городу, по схеме.
- Проверка гипотезы по жалобам («жалуются ли на навязанную страховку»).
- Don't use for: ставки и тарифы (auditlens-market), нормы права (auditlens-research).

## Инструменты
| Вопрос | Инструмент |
|---|---|
| что растёт на неделе | `complaint_signals` |
| почему выросла тема, что за сюжет | `complaint_theme` (days=7 — ровно выборка сигнала) |
| жалобы банка/продукта за период | `complaints_overview` |
| конкретные случаи, проверка гипотезы, «сколько про X» | `complaint_search` |
| рейтинг banki.ru, карточка банка | `bank_profile` |

Продукт — это фильтр `product` («Вклад», «Ипотека»…), а не тема. «Жалобы на
вклады» = `complaints_overview(product="Вклад")`, затем разбор его тем.

## Как найти причину всплеска
1. `complaint_signals` → тема, число за неделю, норма, кратность, рынок, город.
2. `complaint_theme(theme, days=7)` → прочитай ВСЕ жалобы выборки (пересказ,
   цитата, начало текста). Ищи общий сюжет: одно событие, продавца, сервис,
   площадку, сотрудника, город, сумму, формулировку отказа банка. Группы
   похожих жалоб (`similar_groups`) — подсказка, но не весь ответ.
3. Посчитай долю сюжета по самим жалобам выборки («в 6 из 15 — концерт Канье
   Уэста на «Газпром Арене»»). Если нужен точный счёт за другой период —
   `complaint_search(query=<имя/сервис>)`, число из поля `total`.
4. Ответ начинай с сюжета: что произошло, сколько жалоб из скольких, цитата,
   где, что клиенты требуют, что отвечает банк. Потом — остальное.
Готово, когда: назван конкретный сюжет (или честно сказано, что жалобы
разнородны), доля посчитана по выборке, есть цитата и ссылка на тему.

## Как читать числа
- **Норма** (`norm_per_week`) — средняя недельная прошлых недель; `ratio` —
  во сколько раз неделя выше нормы. «×4,2» = в 4,2 раза выше обычного.
- **Рынок** (`market_ratio`, `market_note`) — та же тема у остальных банков.
  «Только у банка» / «в 2 раза сильнее рынка» — значит проблема своя, а не
  отраслевая (сезон, закон, сбой платёжной системы).
- **Эскалация** `escalation_pct` — доля жалоб, где клиент грозит или уже
  обратился в ЦБ/суд/надзор; `escalation_filed_pct` — только уже обратившиеся.
  Рыночная — `market_escalation_pct`. Не путай три числа.
- **Выпуск «Обзора»** — снимок на 07:00: к вечеру живые числа (инструменты)
  могут отличаться на 1–2 жалобы и ×0,2. Показывай живые, разницу объясняй.
- `last_window_incomplete` — последнее окно ещё дописывается; рост может быть
  заниженным.

## Common Pitfalls
1. Абстрактный ответ по названию темы («клиенты недовольны отказами») вместо
   сюжета из текстов — главная ошибка прошлых версий.
2. Число из одного окна, доля из другого: «6 из 11» при сигнале «15 за
   неделю» сбивает аудитора. Долю считай от выборки, которую назвал.
3. Темы — только русскими подписями, коды (chargeback) пользователю не нужны.
4. Не ищи жалобы SQL-запросом по таблице `review` — это старый огрызок;
   жалобы — через инструменты.

## Verification Checklist
- [ ] Период и число совпадают с полем инструмента.
- [ ] Для всплеска назван сюжет с долей и цитатой (или сказано, что сюжета нет).
- [ ] Есть ссылка на тему в «Отзывах» (`link`) и 1–3 ссылки на сами жалобы.
- [ ] «Что проверить» — конкретные шаги в процессах Сбера.
