**AuditLens — Deep-Research платформа для внутреннего аудита банковских продуктов**
v1.0.0

AuditLens отвечает на вопрос аудитора, заданный обычным русским языком, готовым аналитическим отчётом со ссылками на первоисточники, сравнительными таблицами, графиками и PDF-экспортом — за 1–3 минуты вместо часа ручного обхода сайтов банков.

Система заменяет привычный маршрут «открыть 5–10 сайтов банков → скопировать ставки в Excel → склеить в Word» одним запросом вида «сравни условия проектного финансирования подрядчиков ИЖС в трёх банках» или «на что жалуются клиенты в мобильном приложении».

Ключевой принцип, на котором построена платформа: **числа считает детерминированный код, LLM только формулирует**. Каждое число отчёта сверяется с собранными фактами по значению И единице измерения, дельты («на 3,79 п.п.», «в 1,2 раза») пересчитываются арифметически, а сравнительные таблицы и графики строятся вообще без участия модели — галлюцинировать там физически нечему.

──────────────────────────────────────────────────────────
РАЗДЕЛЫ
──────────────────────────────────────────────────────────

01. **Обзор** — ежедневный брифинг: передовица дня, «пульс» из шести метрик, риск-карточки с механикой «Разобраться» и «Спросить ИИ». Все числа — детерминированный SQL, весь выпуск генерируется тремя LLM-вызовами в сутки на всех пользователей и кэшируется.
02. **ИИ-аналитик** — многоагентный deep-research: Conductor строит план → волны агентов (researcher / regulatory / market / reviews / ranking) собирают данные → Analyst пишет отчёт → Critic верифицирует → один проход правок. Агенты пишут находки не в чат, а в типизированный KnowledgeBundle.
03. **Рынок · позиция** — витрина рыночных позиций по каталогу предложений: ранг по ПСК (а не по рекламной ставке), сегменты и подсегменты, медианы и разрывы с лидером, защита от вырожденных метрик.
04. **Отзывы** — риск-радар по корпусу негативных отзывов: 21 тема и 145 regex-паттернов в классах compliance / conduct / ops, детект всплесков на медиане и MAD (устойчиво к самому пику), гео-аномалии на 100 тыс. населения.
05. **Банки** — карточки банков со сводными показателями качества обслуживания, историей изменений условий (SCD2) и методикой расчёта доли решённых обращений.
06. **База знаний** — гибридный поиск (векторный + полнотекстовый, слияние по RRF) по всем прочитанным документам: точные токены вроде «ПСК 24,7%» или «указание 6960-У» находятся дословно, смысловые запросы — по эмбеддингам.
07. **Лазейки** (beta) — отдельный агент ищет схемы обхода комиссий и лимитов клиентами и ИП: доменная таксономия около 40 схем, маскировка персональных данных перед отправкой в модель, дедуп находок.
08. **Для вас** — персональная лента, обучающаяся на поведении: клики, фильтры, вкус-вектор; предгенерация делает открытие мгновенным.

──────────────────────────────────────────────────────────
ЗАЩИТА ОТ ГАЛЛЮЦИНАЦИЙ
──────────────────────────────────────────────────────────

- **Числа с единицами.** Сверка различает природу величины: «комиссия 1,5%» не подтверждается чужим лимитом «1,5 млн ₽», множители раскрываются, производные числа пересчитываются по парам фактов.
- **Доказуемые цитаты.** Дословная цитата факта детерминированно ищется в тексте именно своего источника ещё при записи; не нашлась — доверие факта падает, а утверждение помечается.
- **Запрет сниппетов.** Числа берутся только из полностью прочитанной страницы, никогда из поисковой выдачи.
- **Предмет вопроса.** Критик отдельно проверяет, отвечает ли отчёт на заданный вопрос, а не на смежный; подмена предмета блокирует публикацию и возглавляет директиву правок.
- **Честные пробелы.** Если данных нет, отчёт говорит это первой строкой, а над ним появляется отдельная плашка. Пустая раскладка не может выглядеть успешной: зелёная отметка «проверено» не рисуется поверх таблицы с прочерками.
- **Регрессионный golden-набор.** Эталонные вопросы по всем классам задач с детерминированными ожиданиями прогоняются до выкладки — деградация ловится заранее, а не волной жалоб.

──────────────────────────────────────────────────────────
СБОР ДАННЫХ
──────────────────────────────────────────────────────────

- **Trust scoring источников** — регуляторы (0,98) → официальные сайты банков (0,95) → агрегаторы (0,65) → пользовательские блоги исключаются; поддомены, ведущие чужой бизнес (бронирование, вакансии), к банку не приписываются.
- **Render-on-demand** — если сайт отдал большой HTML, из которого извлеклись крохи текста, страница автоматически дочитывается браузером, а домен запоминается: дальше он рендерится сразу. Списки «этот сайт — SPA» вести руками не нужно.
- **Чтение первоисточников** — тип файла определяется по сигнатуре, а не по расширению: PDF, XLSX, DOCX и HTML-таблицы разбираются в структурированный текст; нечитаемый формат честно называется в пробелах покрытия.
- **Стратегия при блокировке** — на сайтах с защитой от роботов агент получает не тупик, а конкретный обходной путь: искать условия в пресс-релизах банка и отраслевых СМИ.
- **Сегмент клиента** — вопросы про продукты для бизнеса (кредитование юрлиц и ИП, РКО, эквайринг, гарантии) не уводятся в розничные витрины: агенты ищут в разделах «для бизнеса» и корпоративных пресс-центрах.
- **Свежесть как измерение** — поиск умеет ограничивать возраст документов, при дедупликации побеждает свежескачанное поколение страницы, временные ряды не схлопываются в одну точку.

──────────────────────────────────────────────────────────
АРХИТЕКТУРА
──────────────────────────────────────────────────────────

| Слой | Роль |
|---|---|
| **web** | FastAPI + SSE-стриминг, интерфейс на React (in-browser Babel, без сборки), PDF-экспорт через Playwright Chromium |
| **research/v2** | Многоагентный deep-research: Conductor → агенты с инструментами → KnowledgeBundle → Analyst → Critic → Repair |
| **rag** | Загрузка и парсинг страниц, чанкинг, эмбеддинги, гибридный поиск (pgvector + полнотекст, RRF) |
| **sources** | Коннекторы к каталогам и корпусам отзывов, нормализация в SCD2, проверки качества |
| **digest** | Ежедневный брифинг, персональная лента, темы и сигналы |

Инструменты агентов: рыночная витрина, семантический поиск по базе знаний, веб-поиск, чтение страницы, SQL по разрешённым представлениям.

Пять тиров моделей (планирование / навигация / извлечение / нарратив / верификация) настраиваются переменными окружения с деградационной цепочкой — любой тир можно не задавать, система схлопнется в одну модель без правки кода. Переключение между внутренними и внешними моделями — смена пяти строк конфигурации и рестарт.

Внешние зависимости: PostgreSQL с pgvector, объектное хранилище, внешний прокси с SSO (OIDC), OpenAI-совместимый эндпоинт LLM и эмбеддингов, метапоисковый шлюз.
