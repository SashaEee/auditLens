# Сборщик отзывов о ВСП: модель данных

Таблицы `vsp_*` лежат в собственной базе модуля (`VSP_DB_URL`): SQLite для пилота, PostgreSQL на сервере. Схема описана в `src/bank_audit/vsp/storage.py` (SQLAlchemy Core) и создаётся при первом запуске. Приложение AuditLens эти таблицы не читает.

## vsp_branch — справочник отделений

| Поле | Смысл |
|---|---|
| `branch_id` | Внутренний id отделения. |
| `region`, `city` | Регион и населённый пункт, разобранные из адреса ЦБ. |
| `name` | Название по реестру, например «№ 8602/060» — это код ВСП. |
| `address`, `address_key` | Адрес по реестру и ключ сопоставления `город\|улица\|дом`. |
| `lat`, `lon` | Координаты от привязанной карточки 2ГИС или Яндекса (у ЦБ координат нет). |
| `registry_source`, `registry_ref` | Источник реестра (`cbr`) и id подразделения в нём (`FILIAL_SBJ_ID`). |
| `registry_num` | Номер подразделения по ЦБ (`FILIAL_NUM`, «1481/1948/115»); тот же номер есть в карточке Яндекса. |
| `status` | `active` (доп. офис), `cash_center` (кассово-инкассаторский центр, без клиентов), `mobile` (передвижной пункт), `remote`, `closed`. |
| `created_at`, `updated_at` | — |

## vsp_source_branch — карточка отделения в источнике

| Поле | Смысл |
|---|---|
| `source`, `source_branch_id` | Ключ: источник (`2gis` / `yandex` / `domclick`) и id карточки. |
| `branch_id` | Привязка к справочнику. NULL — не привязана. |
| `name`, `address`, `city`, `region`, `lat`, `lon` | Как в источнике. |
| `url` | Ссылка на карточку. |
| `declared_reviews`, `declared_rating` | Заявленное источником число отзывов и рейтинг. |
| `source_status` | Как источник описывает отделение: `open`, `closed`, `moved`, `unknown`. |
| `availability` | Удалось ли до неё дойти: `ok`, `not_found`, `blocked`, `error`. |
| `match_method`, `match_score`, `match_status` | Как привязана: `registry_code` (номер ЦБ в карточке) / `registry_address` / `cross_source` / `manual`; `auto` / `confirmed` / `conflict` / `none`. |
| `last_checked_at` | Дата последней проверки. |
| `raw_json` | Служебные поля источника: организация, число оценок без текста, рубрики; у Яндекса — `cbr_num`, `office_type`, `division_type`. |

## vsp_review — отзыв

| Поле | Смысл |
|---|---|
| `review_id` | `"<source>:<id в источнике>"` — устойчивый id во всей системе. |
| `source`, `source_review_id`, `source_branch_id` | — |
| `branch_id` | Отделение справочника, наследуется от карточки. |
| `rating` | Оценка 1–5. |
| `review_text` | Текст отзыва. |
| `review_date` | Дата создания. У Яндекса — дата обновления, отдельной даты создания у него нет. |
| `author_reference` (`author_ref`) | Хэш (соль, источник, публичный id автора). Имя автора не хранится; соль задаётся в `VSP_AUTHOR_SALT` и в базе не лежит. |
| `organization_reply`, `reply_date` | Ответ банка и его дата. |
| `content_hash` | Хэш текста, оценки и ответа: по нему видно правку. |
| `first_seen_at`, `last_seen_at` | Когда сборщик впервые и в последний раз видел отзыв. |
| `gone_at` | Отзыв пропал из полной выдачи источника. Строка не удаляется. |
| `collection_method` | `public_api` (2ГИС), `page_state` / `internal_api` (Яндекс). |
| `source_url` | Ссылка на отзывы отделения в источнике. |
| `raw_json` | Провайдер (2gis / flamp), дата правки, признак скрытия, лайки, **число отзывов автора** (для проверки «одноразовых» авторов), `confirmed_by` — кем подтверждён отзыв (2ГИС: `sbol` — операцией в СберБанк Онлайн). |

## vsp_review_version — история правок

При изменении `content_hash` сюда пишется прежняя версия отзыва: оценка, текст, ответ и дата ответа, вместе с моментом обнаружения.

## vsp_sync_state — полнота и прогресс по каждому отделению каждого источника

| Поле | Смысл |
|---|---|
| `status` | `never` / `running` / `done` / `failed` / `blocked`. |
| `completeness` | `complete` / `below_declared` / `window` / `partial` / `blocked` / `unknown`. |
| `declared_total` | Сколько отзывов заявил источник. |
| `fetched_total` | Сколько **разных** отзывов получено за последний полный проход (повторы между страницами не считаются). |
| `stored_total` | Сколько хранится, не считая пропавших. |
| `pages` | Сколько страниц пройдено. |
| `cursor`, `sort`, `pass_started_at` | Где продолжить прерванный проход и когда он начался. |
| `newest_review_date`, `oldest_review_date` | Глубина собранной истории. |
| `last_sync_at`, `last_full_at` | Последняя синхронизация и последний полный проход. |
| `errors`, `last_error` | Счётчик ошибок и текст последней. |

## vsp_sync_run и vsp_sync_error

- **`vsp_sync_run`** — прогон: режим, параметры, начало и конец, статус, сводка.
- **`vsp_sync_error`** — ошибки и блокировки по отделениям, с типом (`blocked` / `error` / `crash`) и текстом.

## Персональные данные

- **Имена авторов не хранятся.** Хранится только `author_ref`.
- **В `raw_json` нет данных об авторе:** ни имени, ни ссылок на профиль, ни IP. Есть только число его отзывов.
- **Выгрузка (`export`)** отдаёт отзывы с `author_ref`, без имён.
- **Базу и выгрузки пилота не коммитим.** Они лежат в `workspace/vsp/`, который репозиторий игнорирует.
