# История AI-исследований и доступ по ссылке

Дата: 2026-09-07. Ветка: `codex/loophole-research-history`.

## Поведение

Одно исследование соответствует существующей `loophole_workspace`. Автор видит свои
неудалённые исследования, упорядоченные по последней активности. Название берётся из
первого запроса, если пользователь не задал его явно. Пустое исследование можно создать
кнопкой «Новое исследование». Перезагрузка страницы открывает существующую историю,
не создавая новую запись при каждом посещении.

При открытии восстанавливаются сообщения и сохранённые отчёты. Автор может продолжить
переписку. Незавершённое уточнение не восстанавливает одноразовый токен: пользователь
может повторить или дополнить запрос. История вопросов агента сохраняется как текст.

Удаление устанавливает `deleted_at`, не удаляя workspace, сообщения, отчёты, источники
или результаты. Удалённое исследование недоступно в списке, по прямому идентификатору
и по ранее выданной ссылке. Новое сообщение не снимает отметку удаления.

Ссылка создаётся только по действию автора. Она содержит случайный непрогнозируемый
токен и ведёт на страницу модуля. Владелец ссылки должен войти в AuditLens и иметь
доступ к модулю (пользователь подтвердил это условие). Автор получает обычный режим;
остальные — переписку и отчёты только для чтения. Правила действуют на сервере:
ссылка не разрешает chat/clarify, удаление, выдачу ссылки, импорт или изменение данных.
Просмотр общего исследования не добавляет его в личную историю получателя.

## Контракты

- `GET /api/loophole/workspaces` → `{workspaces: [{workspace_id, name, created_at, last_active_at}]}`.
- `POST /api/loophole/workspace` с `{name: null}` → `{workspace_id}`.
- `GET /api/loophole/history/{workspace_id}` → `{workspace, messages, reports, read_only: false}` только автору.
- `DELETE /api/loophole/workspace/{workspace_id}` → `{deleted: true}` только автору.
- `POST /api/loophole/workspace/{workspace_id}/share` → `{share_url}` только автору.
- `GET /api/loophole/shared/{token}` → `{workspace, messages, reports, read_only}`.
- Сообщения: `message_id, role, content, created_at, report_id` (последнее может быть null).
- Отчёты: `report_id, query, result, created_at`; содержимое — существующий server-side snapshot.
- URL страницы: `/static/loophole/loophole.html?share={token}`.
- Чужой авторский endpoint → 403; отсутствующее/удалённое исследование или неверный token → 404.

## Реализация и проверки

1. Миграция 062: `deleted_at`, `share_token` у workspace и `report_id` у сообщения;
   индексы истории и токена. Существующие сообщения и отчёты сохраняются.
2. Repository/API: фильтрация, мягкое удаление, выдача ссылок, получение истории и отчётов,
   сохранение вопросов и привязки ответа к отчёту. История для LLM берётся с сервера.
3. UI: список, новый/открыть/удалить/поделиться, восстановление и режим чтения;
   ошибки загрузки с повтором; переключение заблокировано во время активного ответа,
   запоздалые ответы загрузки не заменяют выбранное исследование.
4. Тесты: изоляция двух пользователей, отсутствие физического удаления, запрет всех
   мутаций получателю ссылки, автор по своей ссылке, вход/revoke, неверная/удалённая
   ссылка, длинная история, связь отчётов, новый и повторный запуск, UI light/dark/mobile.
5. Команды: `.venv/Scripts/python.exe -m pytest tests/loophole -q`,
   `.venv/Scripts/python.exe -m ruff check src/bank_audit/loophole tests/loophole`,
   `git diff --check`; проверка SQL на локальном PostgreSQL при его доступности.

## Панель истории 2026-09-07

История отображается левой вертикальной панелью внутри поверхности
«AI-исследования». Каждая карточка содержит дату последней активности и название.
Видимое название ограничено 64 символами, включая многоточие; полное название
доступно в подсказке и в доступном названии кнопки открытия.

В правом верхнем углу каждой карточки находится компактный крестик удаления.
Он открывает существующее подтверждение мягкого удаления именно выбранного
исследования. Если удалена не открытая карточка, текущее исследование остаётся
на экране; при удалении открытой загружается следующее либо создаётся новое пустое.
Крестики недоступны во время загрузки, ответа агента и операции истории.

Проверки: браузерный набор истории — **22 passed**, включая положение панели,
дату, лимит в 64 символа, положение крестика и удаление; итоговый `pytest` —
**875 passed, 1 skipped, 13 warnings**, 208,96 секунды. Ruff модуля и его тестов,
а также `git diff --check` прошли без ошибок.
