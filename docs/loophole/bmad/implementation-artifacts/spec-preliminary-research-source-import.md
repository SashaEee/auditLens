## Intent

**Проблема:** новые веб-источники, найденные и распарсенные агентом во время исследования,
не попадают в «Общую базу». Сотрудники ЦК КС не видят их в едином рабочем списке и не могут
взять на последующую верификацию.

**Подход:** после завершения исследования аналитик явно нажимает кнопку переноса найденных
внешних источников в общую базу. Система сохраняет только новые источники с маркировкой
«Предварительно», предварительной вероятностью классификации и связью с исследованием.
Все участники видят такие подозрения во вкладке «Общая база» и могут фильтровать их по
статусу проверки ЦК КС; они доступны очереди верификации, но не считаются опубликованными
кейсами до положительного решения.

## Boundaries & Constraints

**Always:** переносить только серверно подтверждённые источники текущего workspace; сохранять URL,
дату публикации при наличии, дату сбора, provenance исследования и предварительную вероятность;
идемпотентно не дублировать уже существующие записи; показывать подозрительные и непроверенные
записи всем участникам «Общей базы» с явным badge; добавить фильтр проверки ЦК КС со значениями
«Все», «Верифицировано ЦК» и «Ожидает верификации»; при выборе «Верифицировано ЦК» показывать
только записи с завершённой положительной проверкой; сохранять fail-closed RBAC и audit.

**Ask First:** менять права ЦК КС, существующую схему жизненного цикла published cases,
автоматически переносить источники без действия аналитика либо включать в перенос неполученные
страницы, сниппеты поиска или неуспешные fetch.

**Never:** не объявлять предварительную вероятность окончательным вердиктом, не публиковать запись
автоматически, не скрывать непроверенную запись из общего списка только из-за отсутствия решения,
не включать её в результат фильтра «Верифицировано ЦК», не переносить источники другого workspace,
не подменять неизвестную дату публикации датой сбора и не изменять текущий экспорт исследования.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|----------------------------|----------------|
| Успешный перенос | Завершённое исследование с новыми успешно прочитанными источниками | Кнопка добавляет отсутствующие записи в «Общую базу» со статусом «Предварительно» и вероятностью | Показывает число добавленных и пропущенных дублей |
| Повторное нажатие | Те же источники уже импортированы | База не получает копии | Возвращает идемпотентный результат |
| Нет пригодных источников | Только существующие, неуспешные или неполные fetch | Кнопка недоступна либо даёт честное пустое состояние | Ничего не создаётся |
| Работа ЦК КС | Предварительная запись в каталоге | Видны badge, вероятность и provenance; запись доступна для верификации | До решения не становится published |
| Фильтр проверки | В каталоге есть верифицированные и ожидающие записи | «Верифицировано ЦК» показывает только положительно проверенные; «Ожидает верификации» — только нерассмотренные | Отсутствие проверки не выдаётся за отрицательное решение |
| Чужое исследование | Другой workspace либо нет доступа | Перенос и просмотр не раскрывают данные | 403/404 без утечки метаданных |

## Notes for planning

Это явное изменение прежнего ограничения `spec-2-2`, где непроверенные кандидаты не попадали
в общую базу. Новая семантика допускает их в каталог только как предварительные записи для
верификации ЦК КС; правило «не публиковать без решения» остаётся обязательным. Перед реализацией
нужно согласовать единый статус/модель для записи, candidate и evidence snapshot, чтобы не
создать второй параллельный жизненный цикл.
