# Дочерние агенты предварительного исследования

Дата: 2026-09-08. Основание: запрос на ветку от main, младшую модель для анализа
поисковой выдачи и визуальное отображение работы в чате.

## Решение

Основной managed agent получает read-only инструмент `audit_research_subagents`:
до трёх поисковых запросов за вызов, до шести исходных дочерних задач за исследование,
до трёх одновременно. Каждый subagent выполняет поиск существующим адаптером,
затем отдельным Nanobot без инструментов классифицирует до восьми описаний.
Модель: `LOOPHOLE_SUBAGENT_MODEL`, иначе `LLM_MODEL_FAST`. Если обе настройки
пусты, инструмент сообщает об отсутствии модели; основная модель не подставляется.
Рекурсивный spawn и доступ к БД у дочерних агентов отсутствуют.

Основной раннер автоматически создаёт до двух замен неуспешного subagent.
Разметка сохраняется порциями по два материала. Замена получает исходные описания
только необработанных материалов, без повторного поиска; если не выполнен сам поиск,
повторяется исходный запрос. У каждой замены новый идентификатор, изолированный SDK
и событие `retry_of`. При исчерпании попыток основной модели возвращаются накопленные
метки, `pending_sources` и при необходимости `pending_query`. Отмена пользователем
не запускает замену. Общий счётчик считает цепочку замен одной подзадачей.

Маркировка предварительная: `loophole`, `fraud`, `irrelevant`, `insufficient_data`.
Тип материала: `article`, `post`, `comment`, `unknown`. URL и заголовок берутся
только из фактической выдачи, модель возвращает идентификатор и обоснование.
Мошенничество не получает `is_loophole`. Описания не становятся доказательствами:
основной агент читает первоисточник перед извлечением кандидата или выводом
о мошеннической схеме. Предварительные результаты не записываются в каталог.

Каждый subagent имеет отдельный идентификатор и ограниченный контекст. Входы
и публичные результаты маскируются существующими средствами. Общие отмена и
дедлайн ограничивают поиск и LLM; ошибка одной задачи не отменяет другие.
Лимит отдельного поиска и каждой порции анализа: `LOOPHOLE_SUBAGENT_TIMEOUT_SECONDS`
(по умолчанию 180 секунд, допустимо 1–600), но не дольше остатка общего бюджета.
Ожидание свободного слота показывает `queued` и не расходует этот лимит; общий
дедлайн и отмена охватывают также очередь. Дочерняя модель использует полный HTTP-ответ
без скрытого idle-таймера SDK; временем управляет раннер порции. У дочернего HTTP-клиента
TCP/TLS-подключение ограничено 10 секундами, чтобы зависшее рукопожатие быстро
повторялось. Это не ограничивает чтение ответа и не меняет настройки основной модели.
Для Qwen3.6-35B-A3B
дочерний экземпляр использует `chat_template_kwargs.enable_thinking=false`:
классификатор сразу возвращает JSON со строгой схемой `response_format`: допустимые
категории и типы, идентификаторы входных материалов, точное число строк. Ответ
дополнительно проверяется локально, включая уникальность id. При доработке завершения исследования этот
режим также включён для основной модели и экстрактора, если выбрана та же Qwen.
Другие модели сохраняют настройки. Параметр описан в [документации модели](https://huggingface.co/Qwen/Qwen3.6-35B-A3B#instruct-or-non-thinking-mode).
События `subagent` содержат только проверенные публичные поля: идентификатор,
стадию, заголовок задачи, счётчики и предварительные метки с источниками.
Карточки чата показывают поиск, анализ, завершение, ошибку и прерывание.
Ошибки разделяются на `timeout`, `search_error`, `model_error`, `invalid_response`.
В SSE и карточках используются фиксированные безопасные пояснения; в журнале —
код, стадия, тип исключения и длительность, без исходного текста исключения.
Центральный счётчик подзадач включает дочерних исследователей. SDK запускается
с уникальным `session_key`, `ephemeral=True` и временным workspace, удаляемым
после закрытия клиента. Метки видны в текущем чате и передаются основному агенту;
после перезагрузки история восстанавливает сохранённый отчёт, а не карточки прогресса.

## Завершение основного исследования при внешних сбоях

Основание: запуск `513ffcdbb0064ff1a2247c49185f77a8` 2026-09-08 длился
1800 секунд: 1329,8 с ожидания модели, 469,8 с инструментов; 31 поисковый запрос,
19 чтений страниц, ни одного вызова извлечения. Дочерние агенты ответы вернули.

- `LOOPHOLE_MODEL_TIMEOUT_SECONDS=0`: основная модель ожидается без таймаута
  HTTP, idle и всего вызова SDK. Адаптер получает полный ответ существующего провайдера;
  события инструментов и прогресса по SSE продолжаются во время ожидания.
  Положительное значение 1–300 включает ограничение явно. Реальных повторов не более
  одного; heartbeat не считается попыткой. На дочерние экземпляры настройка не влияет.
  Ошибка провайдера не отправляется как дельта текста, чтобы SDK не отменял повтор.
- `LOOPHOLE_NO_PROGRESS_ROUNDS=3`: остановка после последовательных раундов
  без новых прочитанных источников, обработанных страниц или валидных кандидатов.
  Готовый финальный ответ не считается бесплодным раундом. Диапазон 1–10.
- `LOOPHOLE_SEARCH_LIMIT=12` и `LOOPHOLE_FETCH_LIMIT=12`: квоты уникальных
  запросов основных web-tools (диапазон 1–60); повторный запрос или URL использует
  результат текущего запуска, включая безопасный статус недоступного источника.
  Дочерний поиск отдельно ограничен шестью задачами, как описано выше.
- Между раундами сервер автоматически передаёт до двух новых прочитанных страниц
  существующему экстрактору. Сохраняются маскирование ПДн, проверка даты публикации
  и дословной цитаты. Ошибка извлечения не считается пустым успешным результатом.
  Результаты передаются следующему запросу основной модели и доступны при
  повторном явном обращении к инструменту извлечения.
- Под состояние используется один обновляемый блок первого system-сообщения:
  Cloud.ru требует system в начале; SDK готовит копию контекста до `before_iteration`.
- При `time_budget`, `model_timeout`, `model_unavailable`, `no_progress` формируется
  детерминированный частичный отчёт: валидные кандидаты, прочитанные материалы,
  непроверенные поисковые ссылки и недоступные источники. Ссылки не объявляются
  доказательствами. Отчёт сохраняется в истории чата и передаётся через SSE;
  незаконченный текст модели его не заменяет. Каталог автоматически не заполняется.
- `LOOPHOLE_AGENT_TIMEOUT_SECONDS=0`: общий таймер по умолчанию отключён, в том числе
  локально. При явном положительном лимите для закрытия ресурсов резервируется 5%
  бюджета, максимум 10 с. Пользовательская отмена, лимиты инструментов, итераций
  и остановка при отсутствии прогресса сохраняются.

Историческая проверка до отключения таймаутов: широкий запрос по Сберу за 2026 год завершился за 253 секунды
по `model_timeout` следующего шага. Сохранён отчёт на 2418 символов с прочитанным
материалом, непроверенными ссылками и ограничениями; кандидатов нет. Отдельная

извлечение со статусом `completed`, без кандидатов. Это проверка работоспособности
и обработки сбоев, а не оценка полноты поиска или точности классификации.

Независимое review завершено без существенных замечаний. Регрессии проверяют

выполнение, завершение, ошибка. Автоматическое извлечение использует тот же публичный
формат SSE; завершение доставляется и при достижении запрошенного количества находок.
