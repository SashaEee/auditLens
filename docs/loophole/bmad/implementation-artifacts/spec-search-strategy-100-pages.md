## Intent

**Проблема:** агент прекращает поиск после первых 12 уникальных поисковых фраз и 12 попыток загрузки, даже когда не найдено ни одной запрошенной лазейки или мошеннической схемы. Пользователь получает шумную выдачу вместо объяснимого исследования по достаточному числу реально прочитанных материалов.

**Подход:** ввести серверно контролируемую стратегию поиска по новым уникальным URL: цель по умолчанию — пять доказательных находок, явное число из запроса пользователя имеет приоритет, а абсолютный предел — 100 уникальных успешно загруженных страниц с непустым текстом. При достижении 100 страниц результат честно фиксируется независимо от количества находок; при нуле формируется полезный отчёт об охвате, темах материалов и недостающем уточнении.

## Boundaries & Constraints

**Always:** считать страницей только уникальный канонический URL с непустым успешно извлечённым текстом; не считать SERP-сниппет доказательством; сохранять фильтр периода, дедупликацию URL/цитаты, ПДн-маскирование, отмену и общий deadline. Лазейки и мошеннические схемы искать только когда они запрошены, подтверждать чтением первоисточника и показывать раздельно; мошенническую схему не сохранять как лазейку или запись каталога.

**Ask First:** менять внешние поисковые провайдеры, периодный фильтр, модельный провайдер, права доступа, контракт публикации/верификации или БД-схему.

**Never:** не повторять уже прочитанный либо неудачно загруженный URL, не обходить лимит времени, не выдавать отсутствие находок за доказательство отсутствия лазеек, не включать непрочитанные URL в доказательства или PDF и не создавать git-коммит.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Первая выдача без нужной находки | После 12 уникальных поисковых фраз нет требуемой лазейки/схемы | Агент формирует новый кластер фраз и читает только новые URL | Дубли, пустые и неудачные URL не повторяются и не засчитываются |
| Целевое число | Найдено 5 доказательных находок либо явное число пользователя | Исследование завершается до потолка страниц с раздельным результатом по запрошенному типу | Явное число заменяет дефолт, но не отменяет предел 100 страниц |
| Предел 100 с находками | Прочитано 100 успешных уникальных страниц, найдено от 1 до целевого числа | Завершается итоговым отчётом только с подтверждёнными находками | Необработанные SERP URL остаются вне доказательств |
| Предел 100 без находок | Прочитано 100 успешных уникальных страниц без доказательной находки | Завершается полноценным отчётом: точное число, группы по поисковым кластерам и безопасный вопрос для уточнения | Не утверждает, что искомых схем не существует |
| Неудачные загрузки и redirect | URL повторяется, перенаправляется, пустой либо недоступен | Не увеличивает счётчик 100 и не запускается повторно | Причина остаётся в безопасном журнале материалов |

**Acceptance Criteria:**

- Given первые 12 поисковых фраз не дали запрошенного типа находки, when число успешных страниц меньше 100, then агент продолжает новый поисковый раунд без повторного URL.
- Given пользователь просит N лазеек или схем, when до потолка найдено N доказательных находок, then агент завершает исследование с N находками; без явного N использует 5.
- Given прочитано 100 допустимых страниц и найдено меньше цели, но хотя бы одна находка, when формируется итог, then он содержит только доказательные находки и завершается без дальнейшего поиска.
- Given прочитано 100 допустимых страниц и находок нет, when формируется итог, then отчёт содержит число страниц, кластеры поиска и вопрос для сужения запроса, не объявляя отсутствие схем доказанным.
- Given URL был redirect-алиасом, пустой либо недоступной страницей, when учитывается охват, then он не увеличивает счётчик успешных уникальных страниц.

## Design Notes

Предел 100 — верхняя граница исследования, а не обещание добыть заданное число любой ценой. Явное пользовательское число определяет целевой результат до достижения этого предела; при 100 страницах отчёт честно завершает работу даже если цель не достигнута. Группы нулевого результата строятся из серверно зафиксированных поисковых кластеров, а не из SERP-сниппетов как будто они были доказательствами.
