## Intent

Как аналитик,
я хочу включать и отключать разрешённую аналитическую задачу по расписанию,
чтобы получать внутренний результат без хранения или запуска произвольного SQL.

**Критерии приёмки:**

**Дано** аналитик выбирает доступную именованную аналитическую задачу,
**Когда** он включает расписание,
**Тогда** система сохраняет `ScheduledQueryContract v1` с идентификатором и версией запроса, workspace, владельцем, получателем и сроком действия.
**И** raw SQL не сохраняется в контракте.

**Дано** наступает время запуска,
**Когда** scheduler проверяет контракт,
**Тогда** он выполняет задачу только при действующем членстве владельца и получателя, нужных capabilities и неистёкшем сроке.
**И** иначе создаётся одно аудит-событие `schedule_skipped_<причина>` без выполнения запроса.

**Дано** задача успешно завершена,
**Когда** формируется `ScheduledResult v1`,
**Тогда** результат остаётся во внутреннем приватном назначении workspace с ACL владельца и получателя.
**И** TTL не превышает 24 часов, а внешний адресат и автоматический экспорт запрещены.

## Code Map

- `src/bank_audit/loophole/analytics.py`: единственный allowlisted исполнитель
  `execute_analytics_query`; расписание не принимает и не сохраняет raw SQL.
- `src/bank_audit/loophole/scheduled_analytics.py`: серверный реестр именованных
  задач, `ScheduledQueryContract v1`, повторная проверка membership/ownership и
  приватный `ScheduledResult v1` с TTL не более 24 часов.
- `src/bank_audit/loophole/scheduled_analytics_scheduler.py` и
  `src/bank_audit/web/app.py`: отключённый по умолчанию фоновый cron-тикер,
  включаемый только `SCHEDULED_ANALYTICS_ENABLED=1`.
- `src/bank_audit/loophole/web.py`: transport принимает `query_id`, а чтение
  результата проверяет ACL владельца и назначенного получателя.
- `migrations/053_loophole_scheduled_analytics.sql`: контракт и результат без
  колонки raw SQL; внешняя доставка и экспорт в схеме отсутствуют.
- `tests/loophole/test_story_4_4_scheduled_analytics.py` и
  `tests/loophole/test_db_schema_053.py`: наблюдаемые сценарии выполнения,
  отказа по membership, ACL и запрета raw SQL.
