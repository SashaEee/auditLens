- (constraint) PRD: agent works through ReAct; default cap 20 with override; clarification does not consume an iteration; cap returns explained partial result.
- (constraint) SPEC: classifier is sixth independent skill; positive CCKS verdict automatically publishes a case; automatic processing never overwrites manual analyst or CCKS verdicts.
- (constraint) PRD: DB skill is read-only; Telegram secrets only come from environment; XLSX is capped at 10000; PDF has graceful fallback.
- (constraint) UX sources are authoritative for the loophole static UI and require self-hosted assets, inherited tokens, dark-theme synchronization, iframe-responsive layout, Russian labels, accessible controls and explicit error states.
- (decision) AD-1: agent.Agent is the target ReAct orchestration boundary; chat/graph.py adapts its existing chat and SSE contract. chat/tools_nanobot.py remains only as a compatibility shim until behavioral parity is proven, then is removed. Binds: migration path and runtime boundary. Prevents: permanent dual architectures and chat-contract breakage.
- (decision) AD-2: SkillRegistry reads SKILL.md metadata but enables only config.json allowlisted names mapped to registered Python entry points. Binds: skill discovery and loading. Prevents: arbitrary code execution from a directory scan.
- (decision) AD-3: persist redacted structured agent events in agent_audit_log: run lifecycle, tool calls, errors and final status; exclude full prompts, tokens and Telegram secrets. Binds: audit ownership and retention boundary. Prevents: non-auditable execution and secret leakage.
- (decision) AD-4: loophole-classifier is a sixth independent skill over existing classify.py; default batch is 50 records and configurable. Binds: classification invocation boundary. Prevents: classifier duplication and unbounded batch context.
- (decision) AD-9: scheduler service exclusively owns schedule lifecycle and persistent task state; skills submit commands and read typed status. Prevents duplicate schedulers and ambiguous runs.
- (decision) AD-10: audit events include run, user, workspace, redacted request summary, timestamps, duration, tool names and terminal result; never full prompts, payloads, raw LLM outputs or secrets.
- (decision) AD-11: versioned SSE progress events are sent within 15 seconds and on every long step, with run_id and machine code for localized UI.
- (decision) AD-12--AD-16 added after adversarial review: fail-closed authorization, transactional canonical audit schema, per-run factory and cutover gate, read-only DB defence in depth, and atomic manual verdict protection.
