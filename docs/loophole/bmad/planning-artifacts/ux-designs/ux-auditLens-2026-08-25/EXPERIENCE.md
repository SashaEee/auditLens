# EXPERIENCE.md — модуль «Лазейки»

## Foundation

- **Форм-фактор:** десктоп-веб, внутренний инструмент. Рабочий диапазон: от 1280×720 (малый ноутбук) до широких мониторов. Мобильные (<1024px вьюпорта) — вне скоупа v1, но layout не должен ломаться: горизонтальный скролл страницы недопустим, контент деградирует до одноколоночного.
- **Среда исполнения:** SPA в iframe (`/static/loophole/loophole.html`) внутри `.surface`-карточки сайта. Все размеры считаются от геометрии iframe, а не вьюпорта браузера: при вьюпорте 1280px модуль получает ≈992px ширины и ≈600px высоты.
- **UI-система:** дизайн-система сайта auditLens; визуальные токены — {DESIGN.md}. EXPERIENCE.md задаёт только поведенческую дельту.
- **Синхронизация темы:** iframe не наследует `html.dark` родителя. Модуль при загрузке читает класс `documentElement` родительского документа (same-origin) и подписывается на его изменения (MutationObserver), применяя `html.dark` у себя. Недоступность родителя (страница открыта напрямую) — fallback на `prefers-color-scheme`.
- **Vendor-ресурсы:** только саморазмещённые (`/static/vendor/react.min.js`, `react-dom.min.js`, `babel.min.js`, `fonts.css`) — как у основного сайта.

## Information Architecture

Внутри одного выбранного рабочего контекста — три зоны:

1. **Header** — заголовок, счётчик записей, действия: «Парсеры», «Экспорт CSV», «Обновить», «Управление доступом» (admin), переключатель чата (на узких ширинах).
2. **Основная область** — панель фильтров → плавающая панель массовой маркировки (по условию) → таблица записей.
3. **AI-чат** — на широких ширинах правая колонка; на <1100px (ширина iframe) — off-canvas панель поверх контента с кнопкой открытия в header.

Модалки: парсеры (CRUD + live-лог), ручная маркировка вердикта, управление доступом (RBAC). Toast-уведомления. Рабочие контексты базы, AI-исследования и очереди ЦК КС не объединяются на одном экране; их навигация и защищённые административные поверхности определены в `ADAPTIVE-CHAT-SPEC.md`.

Закрытость покрытия: каждая заявленная потребность (просмотр записей, фильтрация, массовая и ручная маркировка, экспорт, управление парсерами, чат с агентом, RBAC) имеет поверхность; каждая поверхность покрыта ключевым сценарием ниже.

## Voice and Tone

- Русский язык везде; технические id (`clarify`, `execute`, `answer`, `new`, `classified`) пользователю не показываются — подписи «Уточнение», «Выполнение», «Ответ» и т.п.
- Тон — рабочий, короткий, без эмодзи: «Записей: 128», «Экспортировано 45 записей», «Не удалось загрузить записи. Повторить?».
- Ошибки всегда содержат действие: не «Ошибка сети», а «Не удалось загрузить записи — [Повторить]».

## Component Patterns

- **Фильтры.** Текстовый поиск с debounce 300–400ms — запрос не уходит на каждое нажатие. Активные фильтры визуально отличимы; «Сбросить» возвращает состояние по умолчанию. Список статусов в фильтре совпадает со статусами, реально отображаемыми в таблице (единый источник `STATUS_OPTIONS`).
- **Таблица записей.** Клиентская сортировка — по клику на заголовок-кнопку (`aria-sort`, доступна с клавиатуры). Выделение строки — только чекбоксом; клик по строке раскрывает детали (отдельная кнопка-стрелка ≥28px тоже раскрывает). Текст в ячейках можно выделять и копировать. Колонки имеют приоритет: при нехватке ширины первыми скрываются «Собрано» и «URL» (URL доступен в раскрытой строке), последними — «Запись» и «Вердикт».
- **Массовая маркировка.** Плавающая панель появляется при ≥1 выделенной строке, прижата к низу таблицы, не перекрывает последнюю строку (резервный padding).
- **AI-чат.** На узких ширинах — off-canvas: overlay + панель 320–380px справа, закрытие по Escape и клику по overlay, состояние разговора сохраняется между открытиями. Фазовый индикатор — локализованные подписи.
- **Модалки.** Escape закрывает, focus-trap внутри, фокус возвращается на открывшую кнопку. Подтверждения деструктивных действий (удаление парсера) — модалкой с явным описанием последствия, не `confirm()`.
- **Экспорт.** Результат — toast-success («Экспортировано N записей») или toast-error с кнопкой повтора, не `alert()`.

## State Patterns

- **Загрузка таблицы:** skeleton-строки или спиннер в теле таблицы; счётчик показывает «…».
- **Ошибка загрузки:** явный error-state в теле таблицы: сообщение + кнопка «Повторить». Пустая таблица («Нет записей») и ошибка визуально различимы всегда.
- **Пустой результат фильтров:** empty-state с подсказкой «Попробуйте изменить фильтры» + кнопка «Сбросить».
- **Toast:** три варианта — info / success / error; error не исчезает автоматически раньше 6с. Один тост за раз, новый заменяет старый.
- **Офлайн/сбой API:** любой fetch с `catch`, переводящий UI в error-state; молчаливых сбоев нет.

## Interaction Primitives

- Все интерактивные элементы — реальные `button`/`a`/`input`, не `div onClick`.
- Клик-мишени ≥28px (стрелки раскрытия, чипы, кнопки закрытия).
- `:focus-visible` кольцо (accent, 2px) на всех контролах без исключения.
- `prefers-reduced-motion`: анимации появления панелей и toast отключаются.
- Горячие клавиши не вводятся (v1), кроме стандартных: Escape — закрыть модалку/панель чата, Enter — submit форм.

## Accessibility Floor

- Контраст текста ≥4.5:1 — шкала ink на paper это гарантирует; `ink-4` только для placeholder.
- Таблица: `scope="col"` на th, `aria-sort` на активной колонке, чекбоксы с `aria-label` («Выбрать запись: {title}»).
- Модалки: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок, focus-trap, возврат фокуса.
- Статусные цвета дублируются текстом/иконкой — смысл не передаётся одним цветом.
- Проверка обеих тем: тёмная тема держит те же контрасты.

## Responsive & Platform

| Ширина iframe | Поведение |
|---|---|
| ≥1400px | Таблица + чат 340–380px; все 9 колонок видны; фильтры в одну-две строки. |
| 1100–1399px | Чат 300px; низкоприоритетные колонки («Собрано», «URL») скрываются; header переносится в две строки. |
| 736–1099px | Чат — off-canvas; таблица на всю ширину; колонки «Собрано»/«URL» скрыты. |
| <736px | Деградация без поломки: одна колонка, горизонтальный скролл только внутри таблицы. |

Вертикаль: высота модуля ограничена iframe (`calc(100vh - 120px)` на сайте). При 600px высоты: header и фильтры компактные (фильтры сворачиваются в одну строку с overflow), таблица скроллится внутри своего контейнера со sticky thead; чат имеет собственный скролл. Двойной скролл страницы недопустим.

## Key Flows

### KF-1. Катя разбирает утреннюю порцию записей (малый ноутбук, 1280×720)

> Катя открывает «Лазейки» на ноутбуке 13". Модуль получает 992×600: чат скрыт за кнопкой в header, таблица занимает всю ширину. Она вводит «кэшбэк» в поиск — таблица обновляется один раз после паузы, без мерцания. Кульминация: она выделяет 6 записей чекбоксами, жмёт «Лазейка» в плавающей панели, получает зелёный toast «Размечено 6 записей» — и ни разу не скроллила страницу горизонтально.

### KF-2. Максим маркирует спорную запись вручную (широкий монитор)

> Максим кликает по строке, читает полный текст, жмёт «Указать вердикт». Модалка открывается, фокус — на первом варианте; он выбирает «Обычный запрос», пишет причину, Enter — toast-success, фокус возвращается на строку. Кульминация: весь путь выполнен с клавиатуры, без мыши.

### KF-3. Ольга работает в тёмной теме вечером

> Ольга переключает сайт в тёмную тему — модуль мгновенно следует за ней: фон, таблица, чат и модалки в тёмных токенах, контрасты сохранены. Кульминация: никакого белого прямоугольника посреди тёмного интерфейса.

### KF-4. Антон удаляет парсер и передумывает

> Антон жмёт «Удалить» у парсера — модалка: «Парсер "banki-forum" и его расписание будут удалены. Записи останутся.» Кнопки «Удалить» / «Отмена». Он жмёт Escape — модалка закрывается, фокус возвращается на кнопку. Кульминация: деструктивное действие требует осознанного подтверждения, отмена — один шаг.
