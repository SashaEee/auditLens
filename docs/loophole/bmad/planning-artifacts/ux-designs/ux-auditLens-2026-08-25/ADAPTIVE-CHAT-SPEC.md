# Спецификация: адаптивные рабочие экраны и панель агента

## 1. Назначение и нормативный приоритет

Документ переводит PRD и UX-spines в проверяемый контракт реализации интерфейса
модуля «Лазейки». Он уточняет поведение на ноутбуках и управление окном чата
агента, но не вводит новые продуктовые возможности.

При конфликте источников действует порядок: PRD (`FR-10`--`FR-12`) определяет
границы рабочих контекстов; `DESIGN.md` определяет внешний вид; `EXPERIENCE.md`
определяет общие паттерны поведения. Поэтому база, AI-исследование и верификация
не могут быть показаны на одном рабочем экране. Формулировку `EXPERIENCE.md` о
едином экране следует применять только внутри одного выбранного контекста.

## 2. Границы и целевой форм-фактор

- Модуль остаётся десктопным внутренним веб-инструментом в same-origin iframe
  `/static/loophole/loophole.html`.
- Целевой минимум -- ноутбук 1280x720: доступная геометрия iframe примерно
  992x600. Мобильная оптимизация не входит в v1, однако корневой документ не
  получает горизонтальную прокрутку при любой ширине.
- Изменения интерфейса ограничены `src/bank_audit/loophole/static/`. Новый
  интерфейс не меняет HTTP/SSE-контракт агента, права доступа, модель данных или
  правила публикации кейса.
- Визуальные токены, тёмная тема, типографика, радиусы и тени наследуются без
  отклонений из `DESIGN.md`. В частности, текст не меньше 11px, клик-мишень не
  меньше 28px, а контраст текста не ниже 4.5:1 в обеих темах.

## 3. Информационная архитектура

### 3.1. Выбор рабочего контекста

Стартовая поверхность предлагает отдельные действия:

| Действие | Доступ | Открываемый экран | Не показывается на экране |
|---|---|---|---|
| «Общая база» | аналитик | фильтры, таблица, экспорт, парсеры и ручная/массовая маркировка | результаты исследования, очередь, карточка решения ЦК КС |
| «Новое AI-исследование» | аналитик | параметры исследования, панель агента, ход выполнения, результаты и первоисточники | общая база и очередь верификации |
| «Очередь верификации» | только ЦК КС | очередь, карточка кейса, первоисточники, решение и статус публикации | база и AI-чат |

Недоступный пользователю пункт не рендерится. Прямой переход без роли ЦК КС
завершается fail-closed экраном «Нет доступа к очереди верификации» и действием
«Вернуться к выбору». Он не раскрывает данные очереди. Скрытие пункта в UI —
только дополнительная защита: сервер обязан перепроверять principal, membership
и разрешение на каждом запросе; при отзыве роли в активной сессии открытая очередь
сразу заменяется тем же экраном доступа без сохранённых данных в DOM.

### 3.2. Защищённые административные поверхности

«Управление доступом» не является четвёртым рабочим контекстом аналитика. Это
отдельный защищённый маршрут администратора модуля, открываемый из релевантного
header. В нём доступны только: назначение и отзыв роли ЦК КС (не более пяти
активных экспертов), статус цели мониторинга и сводный аудит. База, черновики
исследований, очередь и полные технические payload не смешиваются с этой
поверхностью. При прямом переходе без права администратора применяется
fail-closed экран без раскрытия причины отказа или данных.

### 3.3. Каркас каждого контекста

Каждый экран состоит из header, своей основной рабочей области и локальных
модальных окон/toast. Header сохраняет название контекста, кнопку «К рабочим
контекстам», счётчик или статус и только релевантные действия. На малом ноутбуке
действия переносятся на вторую строку; обрезание, скрытие без альтернативы и
горизонтальная прокрутка header запрещены.

## 4. Контракт панели агента

Панель агента существует только на экране «Новое AI-исследование». Она использует
существующий чат-контракт и отображает исключительно состояние текущего
изолированного исследования; база и очередь верификации не встраиваются в чат.

| Состояние | Поведение |
|---|---|
| Широкая ширина iframe (>=1100px) | Панель закреплена справа от результатов: 340--380px при >=1400px, 300px при 1100--1399px. Пользователь может скрыть её кнопкой «Скрыть чат»; результаты сразу занимают освобождённое место. |
| Компактная ширина iframe (736--1099px) | Чат по умолчанию скрыт. Кнопка «Открыть чат» в header открывает off-canvas панель справа шириной 320--380px поверх контента. |
| Пользователь скрыл чат | В header всегда остаётся доступная кнопка «Открыть чат». Состояние разговора, черновик ввода, ход операции и список сообщений не сбрасываются. |
| Пользователь открыл чат | Фокус переводится на заголовок панели; после закрытия возвращается на кнопку, которая её открыла. |
| Закрытие | Кнопка закрытия, Escape и клик по затемнению закрывают off-canvas панель. Закрытие не отменяет уже запущенное исследование. |
| Агент выполняет операцию | Локализованный индикатор фазы («Уточнение», «Выполнение», «Ответ») и понятный статус показываются в панели. Первый промежуточный статус типового запроса должен появиться не позднее 15 секунд. |
| Ошибка/частичный ответ | Панель показывает объяснение и действие «Повторить»; ошибка не заменяется пустым чатом и не выдаётся за успешный ответ. |

На ширине <736px off-canvas панель занимает не более ширины контейнера. Страница
не прокручивается по горизонтали; если таблица/очередь не помещается, прокрутка
разрешена только их собственному контейнеру.

## 5. Адаптивная сетка и вертикальный ритм

| Ширина iframe | Общий layout | Данные |
|---|---|---|
| >=1400px | две колонки в AI-исследовании; чат 340--380px | в базе видны все приоритетные колонки |
| 1100--1399px | две колонки; чат 300px; header в одну или две строки | «Собрано» и URL скрываются первыми, URL остаётся в деталях строки |
| 736--1099px | одна основная колонка; чат off-canvas | таблица/очередь занимают всю ширину; «Собрано» и URL скрыты |
| <736px | одноколоночная деградация без поломки | горизонтальный скролл допустим только у таблицы или очереди |

Высота не задаётся через `height: 100vh` на корне. При высоте iframe около 600px
header и фильтры остаются компактными, а прокрутка разделена: таблица/очередь
имеет sticky header и собственный scroll-container, чат -- собственную область
сообщений. Одновременно активны не более одного вертикального скролла для
основного содержимого контекста и одного -- внутри открытого чата; двойной
скролл страницы запрещён.

## 6. Поведение данных и обратная связь

- Фильтры базы: поиск с debounce 300--400ms, единый `STATUS_OPTIONS`, явный
  «Сбросить». Сортировка доступна с клавиатуры и передаёт `aria-sort`.
- Клик по строке раскрывает детали; выделение выполняется только чекбоксом.
  Отдельная кнопка-стрелка дублирует раскрытие для клавиатуры и имеет мишень
  не менее 28px. Скрытые в адаптивном режиме URL и вторичные поля доступны в
  деталях; клик по интерактивному контролу внутри строки не раскрывает её.
- Загрузка, пустой результат и ошибка -- три разные поверхности. Ошибка содержит
  описание и «Повторить»; счётчик во время загрузки показывает «…».
- Toast имеет варианты info/success/error. Деструктивное действие подтверждается
  модалкой с последствием, focus-trap, Escape и возвратом фокуса; `alert()` и
  `confirm()` запрещены.
- Результат исследования остаётся изолированным до положительного решения ЦК КС.
  Положительное решение публикует кейс автоматически, «Не подтверждено» -- нет;
  повторная попытка публикации остаётся видимой и не создаёт дубликат.

## 7. Контракт жизненного цикла кейса

- Аналитик выбирает первоисточники явно и видит только evidence, доступный его
  workspace. Недоступный или отозванный источник не раскрывает метаданные: действие
  «Передать в верификацию» недоступно до нового явного выбора разрешённых данных.
- Перед отправкой UI показывает человекочитаемое резюме кейса и источников, затем
  отправляет текущую версию. После успешной отправки показывается статус
  «Ожидает решения ЦК КС»; состав submitted-снимка и источники в нём неизменяемы.
  Это не техническая деталь: пользователь не может незаметно изменить кейс, по
  которому примет решение эксперт.
- Карточка очереди показывает только pending-снимок, его первоисточники, поле
  обязательного комментария и три решения: «Уязвимость», «Мошенническая схема»,
  «Не подтверждено». Цвет не заменяет текст решения.
- Решение является одноразовым. Если другой эксперт успел сохранить решение,
  интерфейс получает и показывает уже зафиксированный итог без повторной отправки
  и без сообщения о локальном успехе. «Не подтверждено» завершает маршрут без
  публикации. Для положительного решения статусы публикации отображаются как
  «Публикуется», «Опубликовано» или «Не удалось опубликовать»; повтор доступен
  только для последнего состояния и использует тот же запрос, поэтому не создаёт
  второй кейс.
- Технические идентификаторы, HMAC, command key, `run_id` и machine code не
  показываются пользователю. Для расследования UI даёт понятное сообщение и
  действие «Повторить» либо возврат к допустимому контексту.

## 8. Доступность и тема

- Все контролы -- семантические `button`, `a` или `input`; у каждого есть
  видимое `:focus-visible` кольцо accent 2px.
- Off-canvas панель использует `role="dialog"`, `aria-modal="true"`,
  локализованный `aria-labelledby`, focus-trap и кнопку закрытия с `aria-label`.
- Важный статус не передаётся только цветом; технические id и emoji не попадают
  в пользовательский интерфейс.
- Тема iframe синхронизируется с `html.dark` родителя через `MutationObserver`;
  при прямом открытии применяется `prefers-color-scheme`. Чат, таблицы, модалки
  и toast меняют тему одновременно.

## 9. Приёмочные критерии

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| AC-UX-01 | Открыть модуль на 1280x720 | При iframe около 992x600 все действия header доступны, страница не имеет горизонтального скролла. |
| AC-UX-02 | Открыть AI-исследование при ширине 992px | Чат скрыт, таблица/результаты занимают всю ширину, кнопка «Открыть чат» доступна. |
| AC-UX-03 | Открыть и закрыть чат клавиатурой | Escape закрывает панель, фокус возвращается на «Открыть чат», сообщения и черновик сохранены. |
| AC-UX-04 | Скрыть чат на ширине 1200px | Панель исчезает, результаты расширяются, кнопка повторного открытия остаётся в header. |
| AC-UX-05 | Сузить iframe через 1100px | Данные деградируют по приоритету, URL доступен в деталях, чат не перекрывает основное содержимое до открытия. |
| AC-UX-06 | Переключить тему родительского сайта | iframe синхронно получает/снимает `html.dark`; все поверхности остаются читабельными. |
| AC-UX-07 | Открыть модалку и off-canvas панель | Фокус не уходит за активный слой; закрытие по Escape и возврат фокуса работают. |
| AC-UX-08 | Пользователь без роли ЦК КС открывает URL очереди | Данные и карточка не отображаются, показан fail-closed экран доступа. |
| AC-UX-09 | Создать исследование и перейти в базу | Результаты исследования не появляются в базе до положительного решения ЦК КС. |
| AC-UX-10 | Кликнуть по строке и по её чекбоксу | Клик по строке раскрывает детали; чекбокс меняет только выделение и не раскрывает строку. |
| AC-UX-11 | Отправить кейс в очередь, затем изменить черновик | Эксперт видит неизменяемый submitted-снимок; изменённый черновик не подменяет его. |
| AC-UX-12 | Два эксперта одновременно сохраняют противоположные решения | В UI появляется ровно одно итоговое решение; проигравший запрос показывает его без повторного side effect. |
| AC-UX-13 | Положительное решение, затем сбой публикации и повтор | Видны статусы «Публикуется»/«Не удалось опубликовать»/«Опубликовано»; повтор не создаёт дубликат в базе. |
| AC-UX-14 | Отозвать роль ЦК КС при открытой очереди | Следующий запрос не возвращает данные; UI очищает очередь и показывает fail-closed экран доступа. |
| AC-UX-15 | Открыть административный маршрут без права администратора | Данные ролей, мониторинга и аудита не отображаются; показан fail-closed экран. |
