# Авторизация смены статуса и проверочный стенд каталога «Лазеек»

## Why

Пользователь без роли администратора модуля или участника ЦК КС мог изменить ручной вердикт и статус записи. Это нарушало границу полномочий в каталоге. Одновременно локальный стенд не содержал таблицу из актуального контракта каталога и возвращал HTTP 500 вместо записей для проверки исправления.

## Capabilities

- **CAP-1 — Серверная авторизация ручного вердикта**
  - **intent:** Только пользователь с активным membership и ролью `module_admin` либо `ccks_expert` изменяет ручной вердикт, статус и связанную базу знаний записи.
  - **success:** Любая одиночная или массовая операция неавторизованного пользователя получает 403 и не меняет запись, KB или аудит; обе разрешённые роли успешно выполняют операцию.
- **CAP-2 — Интерфейс без ложных действий**
  - **intent:** Пользователь видит и использует действия смены вердикта только при явном серверном `capabilities.can_mark_verdict === true`.
  - **success:** При отсутствии, ложном или некорректном разрешении кнопки и модаль недоступны; после 401/403 интерфейс закрывает модаль и удаляет действия.
- **CAP-3 — Воспроизводимый каталог для проверки**
  - **intent:** Локальный стенд запускает каталог на актуальной схеме и показывает тестовые случаи в «Общей базе».
  - **success:** `/healthz` и `/readyz` возвращают 200, `/api/loophole/catalog` возвращает 200 и три тестовые записи со статусами `preliminary` или `published`, которые видны в браузере.

## Constraints

- Сервер проверяет право на каждом защищённом запросе; клиентские claims, `workspace_id` и видимые контексты не предоставляют привилегию.
- Для ручной проверки RBAC `LOOPHOLE_DEV_GRANT_ALL` не заменяет активное membership и фактическую роль пользователя.
- До запуска каталога локальная БД содержит `060_loophole_preliminary_import.sql` и `061_loophole_research_source_publication.sql` в `schema_migrations.migration_name`.
- Тестовые записи предназначены только для локального стенда и не являются исследовательскими или производственными данными.

## Non-goals

- Изменение модели SSO, Authentik/OIDC или правил назначения ролей.
- Предоставление права смены статуса обычному пользователю каталога.
- Публикация тестовых записей или миграций в производственный контур.

## Success signal

Пользователь без привилегированной роли не может изменить статус даже прямым запросом, а администратор модуля или участник ЦК КС может. В локальном браузере «Общая база» показывает три тестовые записи без ошибки загрузки.
