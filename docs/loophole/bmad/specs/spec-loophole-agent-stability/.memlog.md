- (capability) CAP-1 Ретраи транзиентных ошибок LLM: все вызовы loophole (основная модель, clarify, extract, subagents) повторяют connection error/TLS/5xx с бэкоффом; успех — мок-тест транзиента завершается успехом, а не model_unavailable
- (capability) CAP-2 Конечные таймауты основной модели: connect-timeout ~10 с и конфигурируемый read-таймаут вместо timeout=None при дефолтных env; успех — мок зависшего TLS прерывается по connect-timeout
- (capability) CAP-3 Таймаут ответа внутри порции subagent: зависший chat() классификатора прерывается HTTP-таймаутом до 180-с дедлайна порции и ретраится; успех — исчезновение серий code=timeout elapsed_seconds=180.0
- (capability) CAP-4 Смягчение фильтра даты публикации: источник без tz-aware published_at не исключается, а получает пониженное доверие/оценочную дату; успех — запрос с месяцем/годом по форумам возвращает кандидатов
- (capability) CAP-5 Subagent-ветка из коробки: цепочка деградации LOOPHOLE_SUBAGENT_MODEL → LLM_MODEL_FAST → LLM_MODEL_NAME устраняет subagent_model_not_configured при типовой конфигурации
- (capability) CAP-6 Ретраи инструментов: транзиентные сбои web_search/web_fetch/extract_loopholes повторяются до конвертации в fail-closed коды; успех — единичный обрыв извлечения не помечает источник навсегда
- (constraint) Fail-closed по безопасности (RBAC, PII-маскирование, READ-ONLY SQL) не ослабляется — смягчается только фильтр даты публикации
- (constraint) Механизм ретраев повторяет паттерн research/llm_throttle.py, а не изобретает второй; принцип «числа считает код, LLM формулирует» не нарушается
- (constraint) Обратная совместимость env LOOPHOLE_*; тесты без сети и реальной БД по соглашению проекта
- (decision) Non-goals: расширение поискового контура SearXNG/прокси, ослабление отбора кандидатов (дословная цитата), переработка UX/SSE — вне скоупа
- (assumption) Connect-timeout и разумный read-таймаут допустимы для основной модели, несмотря на исторический фикс «0 отключает таймеры» (грабля AGENTS.md про прерывание модели таймером)
