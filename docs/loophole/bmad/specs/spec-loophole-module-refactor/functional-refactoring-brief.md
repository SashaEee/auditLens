# Функциональный бриф: рефакторинг модуля «Уязвимости»

## 1. Результат рефакторинга

Модуль «Уязвимости» становится единым внутренним продуктом для обнаружения, исследования, проверки, автоматической публикации и использования сведений об уязвимостях и мошеннических схемах. Он объединяет три изолированных рабочих контекста:

1. **База уязвимостей** — накопленные, проверенные и опубликованные случаи.
2. **AI-исследование** — отдельная сессия поиска и анализа по запросу аналитика.
3. **Верификация ЦК КС** — служебная очередь решений для пяти уполномоченных экспертов.

Техническая основа — модульный агент в `src/bank_audit/loophole/agent/`, заменяющий монолит возможностей из `chat/tools_nanobot.py` без разрыва текущего чат-интерфейса.

## 2. Пользователи и права

| Роль | Цель | Доступ |
|---|---|---|
| Аналитик | Найти, изучить, экспортировать или инициировать проверку кейса | Стартовый экран, база, AI-исследования, экспорт, передача в очередь |
| Эксперт ЦК КС | Оценить доказательства и вынести решение | Все возможности аналитика плюс очередь и вынесение вердикта |
| Система/агент | Собрать, классифицировать данные и подготовить результат | Только строго определённые skills и инструменты |

Внешние пользователи и пользователи без внутреннего доступа в первую версию не входят.

## 3. Целевой пользовательский цикл

```text
Стартовый экран «Уязвимости»
 ├─ База уязвимостей → поиск/фильтры/детали → экспорт
 ├─ Новое AI-исследование → результаты и источники → экспорт
 │                                              └→ передать на верификацию
 └─ Очередь ЦК КС (только роль) → вердикт + комментарий + аудит
                                         └→ «Уязвимость» / «Мошенническая схема»
                                              → автоматическая публикация в базе
```

Ключевой принцип: база, исследование и верификация — последовательные части одного процесса, но не один перегруженный экран.

## 4. Функциональные требования

### FR-1. Стартовый экран

- Заголовок: «Уязвимости и мошеннические схемы».
- Вводный текст объясняет возможность исследовать известные случаи или провести собственное исследование.
- Отображаются две большие карточки: «Исследовать выявленные уязвимости» и «Запустить исследование».
- Для ЦК КС показывается компактная карточка очереди с числом ожидающих кейсов; для остальных ролей она скрыта.

### FR-2. База уязвимостей

- Поиск и фильтрация по типу, статусу верификации, источнику, банку, периоду и тексту.
- Тип кейса отделён от статуса процесса: `Уязвимость`, `Мошенническая схема`, `Не подтверждено` — вердикты; `Не проверено`, `Подтверждено`, `Отклонено` — статусы.
- Доступны детали с доказательствами, источниками и историей решения.
- Доступны экспорт текущей выборки и всей базы в XLSX/CSV; PDF используется для отчётного сценария.

### FR-3. AI-исследование

- Сценарий открывает отдельное чат-рабочее пространство без таблицы базы.
- До первого запроса показываются назначение, поле ввода и примеры запросов.
- После выполнения показываются результаты, источники, использованные инструменты и статус.
- Экспорт AI-исследования содержит листы «Результаты», «Источники», «Параметры исследования».
- Каждый потенциальный кейс передаётся на верификацию; генерация AI сама по себе не публикует его в базе.

### FR-4. Верификация ЦК КС и автоматическая публикация

- Очередь показывает ожидающие проверки, назначенные эксперту и завершённые кейсы.
- Карточка содержит описание, доказательства, источники и историю анализа.
- Эксперт выбирает `Уязвимость`, `Мошенническая схема` или `Не подтверждено` и оставляет комментарий.
- Сохраняются автор, дата/время, вердикт, комментарий и последующие изменения.
- Вердикт `Уязвимость` или `Мошенническая схема` автоматически публикует кейс в общей базе. `Не подтверждено` не публикуется.

### FR-5. Агентский цикл

- Профильные задачи выполняются в цикле ReAct: рассуждение → инструмент → observation → следующий шаг или финальный ответ.
- При недостатке параметров агент задаёт уточняющие вопросы без расходования итерации.
- Приоритет лимита: аргумент `Agent.run`, `LOOPHOLE_AGENT_MAX_ITERATIONS`, `config.json`, значение по умолчанию 20.
- При исчерпании предела агент возвращает лучший доступный ответ с объяснением.
- Каждый запуск возвращает структурированный ответ и перечень применённых инструментов.

### FR-6. Skill-архитектура

Каждый skill имеет собственную директорию, `SKILL.md` с валидным frontmatter, `scripts/` для tool-обёрток и сервисов, `references/` для инструкций. `SkillRegistry` загружает skills, объединяет tools и фрагменты промптов.

| Skill | Возможности |
|---|---|
| `web-search` | Поиск, загрузка URL, извлечение и сохранение записей |
| `parser-creator` | Создание, запуск и получение статуса парсеров источников |
| `telegram-parser` | Распознавание, нормализация и создание Telegram-парсеров |
| `db` | READ-ONLY SQL и загрузка таблиц для чата |
| `reports` | Формирование XLSX/PDF с единым набором фильтров |
| `loophole-classifier` | Разовая и пакетная классификация записей через отдельную функцию модуля |

### FR-7. Loophole-classifier как функция модуля и skill

- Создаётся отдельная функция модуля классификации, которую вызывает skill `loophole-classifier`.
- Функция поддерживает разовый анализ одного кейса и пакетный анализ записей БД.
- Пакетный режим принимает фильтры: банк, период, текстовый запрос, `only_loophole`, статус; также принимает конфигурируемые лимиты выборки и размера батча.
- До обработки функция исключает записи с ручными вердиктами аналитиков или ЦК КС.
- Функция возвращает результаты классификации, причины/уверенность, число обработанных и пропущенных записей, применённые фильтры и информацию об ограничениях.
- Skill не содержит дублированной бизнес-логики: он валидирует вход, вызывает функцию и превращает результат в ответ агентского цикла.

### FR-8. Экспорт и API

- `POST /api/loophole/export` поддерживает `xlsx` и `pdf`; заглушка PDF `501` удаляется.
- Общий сервис экспорта применяется для `/export` и `/export/csv`.
- Фильтры запроса: `bank_slugs`, `period_from`, `period_to`, `query_text`, `only_loophole`, `status`.
- XLSX содержит `record_id`, `title`, `url`, `domain`, `bank_slug`, `keyword`, `trust_score`, `is_loophole`, поля verdict, статусы и метаданные текста; у таблицы автоширина колонок, фильтр и закреплённая шапка.

## 5. Нефункциональные требования

- DB skill запрещает DDL/DML и любые не-READ-ONLY запросы до выполнения.
- Classifier не меняет ручные вердикты.
- `TG_API_ID` и `TG_API_HASH` не попадают в skill и берутся только из окружения.
- Ошибка одного skill возвращается как observation и не обрушивает агентский цикл целиком.
- При недоступности Playwright/браузера PDF возвращает понятную деградирующую ошибку.
- XLSX ограничивается 10 000 записями; превышение требует сузить фильтр.
- Все вызовы агента, операции classifier, решения верификации и автоматические публикации имеют аудит-след.
- Целевое время первого промежуточного ответа типового запроса — не более 15 секунд.

## 6. Границы и миграция

В scope: новый пакет `agent/`, реестр skills, перенос существующих tools, конфигурация, XLSX/PDF, интеграция с `nanobot_agent.py` и `graph.py`, переходный compatibility shim, интерфейсные потоки базы/AI/ЦК КС, classifier-функция и шестой skill.

Не в scope v1: публичный интерфейс для клиентов, управление Telegram-аккаунтами, замена существующей авторизации, удаление legacy-файлов до доказанного поведенческого паритета.

Миграция выполняется поэтапно: инфраструктура → перенос шести skills → адаптация chat-агента → экспорт и classifier → регрессия и визуальная проверка. `tools_nanobot.py` удаляется только после успешного прохождения полного набора проверок.

## 7. Приёмка и проверка

| Область | Проверка |
|---|---|
| Пользовательские потоки | Демонстрация: вход → база/исследование; роль ЦК КС → очередь → вердикт → автоматическая публикация |
| Изоляция контекстов | В AI-исследовании таблица базы отсутствует; AI-результаты не публикуются до вердикта |
| Права и аудит | Нероль ЦК КС не видит очередь; решение и публикация содержат автора, время, вердикт и комментарий |
| Агент | Тесты лимита итераций, уточнения без списания итерации, partial-ответа, загрузки skills и compatibility shim |
| Classifier | Тесты разового кейса, фильтрованной пакетной обработки, лимитов, пропуска ручных verdict и аудита |
| Экспорт | Тесты XLSX/PDF, фильтров, лимита 10 000 и graceful fallback PDF |
| Регрессия | `pytest` по модулю loophole и `ruff check` затронутых файлов без новых ошибок |

## 9. Уточнения архитектуры

- Аудит запусков агента и операций classifier хранится в `agent_audit_log` как redacted structured events с обязательным `run_id`; запись обязана быть транзакционной.
