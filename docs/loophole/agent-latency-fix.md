# Ограничение длительности исследования «Лазеек»

Дата: 2026-09-07. Ветка: `codex/loophole-research-history`.
Статус: реализация, итоговые автоматические проверки и живая проверка ограничения
времени выполнены. Локальный сервис перезапущен. Приёмка пользователем ожидается.

## Основание и ожидаемое поведение

Пользователь разрешил реализовать исправления из
[диагностики задержки](agent-latency-analysis.md) на запросе
«Найди 1 лазейку по кредитным картам за 2026 год».

Работа агента ограничена настраиваемым общим бюджетом времени
(начальное значение — 180 секунд). При исчерпании бюджета агент завершает работу
без дополнительного обращения к модели, сообщает причину остановки и сохраняет
полученный ответ в истории. Отмена пользователем остаётся отдельным событием.

Явно указанное количество ограничивает поиск: после получения необходимого числа
AI-кандидатов с прочитанными допустимыми источниками агент формирует результат.
Дата публикации проверяется и для периода, заданного только годом. Сниппет или
прочитанная страница сами по себе не считаются найденной лазейкой. Статус
AI-кандидата не заменяет решение эксперта ЦК КС и не публикует запись в каталоге.
Без ограничения количества сохраняется методология широкого исследования.

Фактический набор инструментов SDK очищается перед регистрацией разрешённых
приложением классов. Неявные `spawn`, `long_task`, `message`, `complete_goal`
недоступны исследователю; иначе фоновые subagent-задачи обходили бы бюджет запуска.
Явно переданные приложением инструменты parser/healer сохраняются.

Сетевые инструменты не должны блокировать цикл обработки запросов. Параллелизм
ограничивается на уровне процесса; отменённый вызов продолжает занимать слот до
физического окончания синхронной операции. Рабочий поток не владеет общей сессией
БД и не изменяет контекст исследования. Запоздалый результат отменённого вызова
не должен попадать в историю, источники или находки.
Служебный кэш прочитанных страниц и поиска сохраняется: он использует собственную
короткую сессию БД внутри рабочего потока и может заполниться после отмены ожидания.
Это не изменяет пользовательское исследование.

Во время ожидания интерфейс получает безопасные этапы прогресса. Полное
маскирование персональных данных в итоговом тексте сохраняется.

## Окружение и границы изменения

Локальный процесс Windows использует SearXNG через опубликованный порт
`http://127.0.0.1:8888`. Контейнерное окружение сохраняет адрес
`http://searxng:8080`. Секреты и полный `.env` в документацию не включаются.

Для локального запуска в игнорируемом `.env` явно закреплена
`LOOPHOLE_NANOBOT_MODEL=MiniMax-M2.7`. FAST/SMART и адрес провайдера сохранены.
Текущий `GET /models` содержит семейство MiniMax; GPT-4.1 и gpt-oss из проектной
инструкции в нём отсутствуют. Поэтому отсутствующие идентификаторы не использованы.
В другом окружении нужно выбрать поддерживаемую его провайдером модель.

До закрепления выполнена одна синтетическая проба M2.7 через настоящий nanobot:
два модельных вызова, один безвредный инструмент с постоянным ответом, корректный
финальный текст; 6,123 секунды. Настоящие источники, поиск и БД проба не вызывала.
Артефакт: `workspace/qa/minimax-m27-tool-probe-20260907.json`.
Поддержка OpenAI tool calling описана в
[официальном контракте MiniMax](https://platform.minimax.io/docs/api-reference/text-openai-api).
Выбран обычный M2.7; его стандартные ставки ввода/вывода совпадают с M3 для ввода
до 512k токенов на дату проверки, а highspeed стоит дороже:
[опубликованные тарифы](https://platform.minimax.io/docs/guides/pricing-paygo).

Проба подтверждает узкую совместимость вызова инструмента, не качество исследования.
Исторический замер Gemini нельзя переносить на другую модель или считать чистым
сравнением скорости разных провайдеров.

Параметры реализации:

| Ограничение | Значение | Настройка |
| --- | ---: | --- |
| Исследование | 180 секунд | `LOOPHOLE_AGENT_TIMEOUT_SECONDS` |
| Синхронные поиски и загрузки в одном процессе | 4 | `network_io.NETWORK_CONCURRENCY` |
| Ожидание сетевого инструмента, включая свободный слот | 45 секунд | `network_io.NETWORK_TIMEOUT_SECONDS` |
| Извлечение AI-кандидатов моделью | 45 секунд | Таймаут HTTP и async-вызова, SDK-повторы отключены |
| Обновление безопасного прогресса | 5 секунд | Интервал managed agent |

Остановка ожидания синхронного I/O не является принудительным завершением потока:
физическая операция ограничена таймаутами сетевого клиента. Поэтому слот остаётся
занятым, пока операция не закончится. После остановки исследования дополнительные
LLM-вызовы для оформления частичного ответа не требуются.
Активная работа ограничена общим бюджетом; ожидание закрытия ресурсов дополнительно
ограничено двумя секундами. Таймер работает независимо от того, продолжает ли
SSE-клиент читать события. Зависание закрытия помечается `cleanup_timeout` и не
должно превращаться в пользовательскую отмену.
Уточнение запроса и сборка prompt до создания агента, а также финальная запись
audit/history/ResearchCase в БД после выполнения не входят в эти 180 секунд.
Это ограничение работы агента, а не безусловный SLA всего HTTP-запроса.

## Проверка

До утверждения результата требуются:

- Поведенческие тесты параллельности, доступности цикла событий, отмены и отсутствия
  поздних изменений контекста; проверка ограничения работающих потоков.
- Тесты общего дедлайна, завершения по количеству, сохранения частичного ответа,
  маскирования, истории, авторских прав и режима чтения по ссылке.
- Проверка SearXNG через настоящий `/search`, а не только главную страницу.
- Полный `pytest`, Ruff изменённых файлов и модуля, `git diff --check`.
- Отдельное обозначение ограничений проверки на настоящем провайдере: быстрый
  ответ без допустимых доказательств сам по себе не подтверждает качество поиска.

настоящий JSON `/search` — HTTP 200, 39 результатов за 3127 мс;

набор разрешённых публичных полей с маскированием строк. Полные тела источников
