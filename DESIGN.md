# DESIGN.md — как делать интерфейс «Уязвимостей», не выбиваясь из AuditLens

Правила для агентов и разработчиков, которые меняют интерфейс модуля
`src/bank_audit/loophole/static/` (`loophole.html`, `loophole.jsx`, `loophole.css`).
Вкладка живёт во фрейме внутри AuditLens и должна выглядеть и вести себя как остальные
вкладки сайта. Эталон системы — вкладка «Отзывы» основного сайта.

Источники правды, по убыванию:
1. **Утверждённый макет** задачи, если он есть. Макет — контракт на раскладку, тексты
   и поведение, а не на «стиль примерно такой». Новый экран или заметно другая раскладка
   начинается с макета, согласованного с владельцем продукта, и только потом — с кода.
2. **Этот файл** и **тесты**, которые его закрепляют (§9). Если правило здесь расходится
   с тестом, прав тест, а этот файл нужно поправить.
3. Существующий код модуля. Сначала найди готовый паттерн (§6), потом пиши новый.

`design-qa.md` — журнал проверки прежнего макета от 31.08. Часть решений оттуда
(красная основная кнопка, таблица на 9 колонок, CSV) заменена макетом 27.09, поэтому
правил для новых правок он не задаёт.

## 0. Чек-лист перед коммитом

- [ ] Цвета — только токены (`var(--…)`), литералов вне `:root` / `html.dark` нет.
- [ ] Основная кнопка чернильная. Красный — только риск, фиолетовый — только мошенническая схема.
- [ ] Текст по-русски, без эмодзи, без внутренних кодов; банки по названию.
- [ ] Есть состояния загрузки, пустоты и ошибки (с «Повторить»); ошибка не выглядит как «пусто».
- [ ] Всё работает с клавиатуры, фокус виден, у слоёв есть ловушка фокуса и `Esc`.
- [ ] Проверено на ширинах фрейма 1208, 948 и 390 px, в светлой и тёмной теме,
      без горизонтальной прокрутки страницы.
- [ ] Права не угаданы на клиенте: вкладки и действия приходят с сервера (`/contexts`).
- [ ] После правки `loophole.jsx` пересобран `loophole.js` (`node scripts/build_loophole_js.mjs`),
      и оба файла в коммите.
- [ ] Новое поведение закрыто браузерным тестом, `pytest tests/loophole` зелёный.

## 1. Как устроен модуль

- `loophole.html` — оболочка фрейма: саморазмещённые React и шрифты из `/static/vendor/`,
  синхронизация темы и подключение `loophole.js`. Внешних CDN нет и не будет (закрытый контур).
- `loophole.jsx` — исходник интерфейса. **Страница грузит предсобранный `loophole.js`**:
  Babel в браузере стоил 1,3 с на обычном ПК и 5,5 с на слабом. После любой правки JSX запусти
  `node scripts/build_loophole_js.mjs`. Контрактный тест сверяет sha256 исходника с шапкой
  собранного файла и упадёт, если забыть. Остальной сайт (`app.jsx`) по-прежнему без сборки.
- `loophole.css` устроен сверху вниз:
  1. палитра;
  2. алиасы наследия;
  3. база;
  4. компоненты по разделам;
  5. раздел «Ширина iframe» (адаптивность);
  6. блок **«Наследие модуля»** (панель «Добавить источник» и модал парсеров).

  Новые правила идут **выше** блока наследия: тесты разбирают только часть файла до него.
  Сам блок не перекрашивай и не переноси — панель скрыта сервером и ждёт решения автора модуля.
- Сервер ставит к `loophole.js/jsx/css` метку `?v=<mtime>` (`web/app.py`), кэш сбрасывается сам.
- Прокручивается документ фрейма, а не внутренние контейнеры: вкладки и шапка карточки
  прилипают к его верху.
- **Права решает сервер.** Первым идёт запрос `/contexts`, до него данные не запрашиваются.
  Вкладки и действия — ровно те, что пришли в `contexts` и `capabilities`.
  - 401/403 — экран отказа;
  - сетевой сбой — «Сервис недоступен» с повтором;
  - показывать что-либо «по роли» на клиенте после отказа сервера нельзя.

## 2. Цвет

Палитра в `loophole.css` — дословная копия токенов `:root` и `html.dark` из
`src/bank_audit/web/static/index.html`. Тест `test_iframe_shell_theme` сверяет 25 токенов.
Чтобы поменять цвет, сначала меняй его в `index.html` (для всего сайта), потом копируй дословно
в модуль. Своих палитр в модуле не заводи.

| Смысл | Токены | Где |
|---|---|---|
| Поверхности | `--paper` (поле страницы), `--paper-2` (подложки, поля ввода), `--surface` (карточки, листы) | фон |
| Текст | `--ink` (основной), `--ink-2` (вторичный), `--ink-3` (подписи, мета), `--ink-4` (неактивное, штрихи) | текст, иконки |
| Линии | `--hair` (разделители), `--hair-2` (рамки контролов) | границы |
| Риск | `--accent`, `--accent-ink` (текст на светлой подложке), `--neg` | уязвимость, ошибка, удаление |
| Мошенническая схема | `--legal` | метка и плитка схем |
| Выбор и фокус | `--select`, `--select-soft` | фокус, выделенная строка, активный фильтр, ссылки |
| Сбер | `--sber`, `--sber-soft` | название банка «Сбербанк» |
| Готово / проверено | `--pos` | «проверено экспертом», успех |
| Ждёт / внимание | `--warn`, `--warn-ink` (текст) | «ждёт проверки», предупреждения |
| Подсветка поиска | `--qhl` | `mark.lp-hl` |

Правила:
- **Основное действие — чернильная кнопка** (`--ink` на `--paper`). Красная заливка — только
  у опасного действия (`.lp-btn-danger`) и у уведомления об ошибке. Красный вообще означает
  только риск. Не используй его для «важного» или «нового».
- **Фокус и выделение — графит `--select`**, не красный.
- Вне `:root` / `html.dark` запрещены литералы: `#hex`, `rgb()`, `hsl()`, `oklch()`, `lab()`,
  `lch()`, `hwb()`. Можно `var(--…)`, `color-mix(in oklab, var(--…), transparent N%)`,
  `transparent`, `currentColor`.
- Контраст текста — не ниже 4,5:1 в обеих темах. На подложке выбора (`--select-soft`)
  вторичный текст темнеет на ступень: `--ink-2` вместо `--ink-3`.
- Тёмную тему не рисуй вручную: класс `html.dark` ставит скрипт синхронизации в
  `loophole.html`, токены переключаются сами.

## 3. Шрифт

- **Geist** — весь интерфейс: 13 px в контролах, 14 px в тексте, 15 px у заголовков записей.
  Минимум — **11 px**; единственное исключение — подписи плиток на телефоне (10 px).
- **Числа — табличными цифрами** (`font-variant-numeric: tabular-nums`, класс `.lp-tnum`).
- **Source Serif 4** (`var(--serif)`) используется в пяти местах:
  - заголовок страницы (28 px);
  - крупные числа плиток;
  - фрагменты источника и цитаты;
  - комментарии в истории записи;
  - заголовки листов.
- **JetBrains Mono** (`var(--mono)`) — только клавиши (`.lp-kbd`) и код в ответе агента.
- Надстрочник (eyebrow): 11 px, 600, `letter-spacing: .06em`, прописные, `--ink-3`
  (`.lp-eyebrow`, `.lp-kl`, `dt`, `.lp-rsec h3`).
- У заголовков `text-wrap: balance`, у абзацев `pretty`, ширина текста — не больше `66ch`.
  Заголовок в списке — не больше 2 строк, в карточке — не больше 3.

## 4. Тексты

- Только по-русски. Внутренние ключи и коды на экран не выходят: переводи словарём
  (`KIND_LABELS`, `AUDIT_ACTION_LABELS`, подписи фаз), неизвестный код показывай как есть.
- Термины одни и те же везде:
  - «уязвимость», «мошенническая схема», «не подтверждено», «без вердикта»;
  - «эксперт ЦК КС», «ждёт проверки», «проверено экспертом»;
  - «исследование».
- Банк — названием (`bankName`). Сбербанк выделяется зелёным (`bankClass`). Неизвестный банк
  (`""`, `all`, `generic`, `other`) не показывается вовсе, никаких «—» на его месте (`knownBank`).
- Числа форматируй через `fmtInt`: пробел разделяет тысячи, в дробях запятая. Проценты — целые.
  Склонения — через `lpPlural`.
- Даты — через `fmtDay` и `fmtDate`. Время показывай, только если оно известно: «00:00» —
  вымышленная точность.
- Подпись у числа говорит, что посчитано: «ждут проверки», «новые находки за 7 дней».
  Если данных нет, так и пиши — «пока нет», а не «0».
- Во внутреннее не заходи: оценка доверия источника, аргументы и ответы инструментов агента
  на экран не выводятся. Вероятность показывается только у находок.
- Эмодзи не используются. Иконки — inline SVG из `LP_ICONS` (16×16, штрих 1,5,
  `currentColor`) через `<Icon name="…"/>`. Новая иконка добавляется в `LP_ICONS`.
- Кнопка называет действие: «Показать ещё», «Выгрузить в Excel», «Исследовать глубже».
  Ошибка говорит, что случилось и что сделать, и даёт повтор.

## 5. Раскладка

- **Страница** (`.lp-app`): поле 28 px, на узких экранах 16 px; ширина до 1480 px.
- **Шапка** (`.lp-ph`): надстрочник, заголовок с засечками, пояснение до 78 знаков в строке,
  действия справа.
- Под шапкой — **липкая полоса вкладок** `.lp-tabs` с материалом: размытие и полупрозрачный фон.
- **Главный паттерн — «список + карточка»** (`.lp-split`). Слева список записей, справа
  карточка выбранной, у неё своя вертикальная прокрутка и липкая шапка с навигацией.
  В «Очереди» то же самое: `.lp-qsplit`, список 280–360 px.
- **Фильтры** (`.lp-fhead`):
  - поиск (40 px, клавиша `/`);
  - сегменты `.lp-seg` со счётчиками;
  - выпадающие `.lp-dd` с поповером `.lp-pop`;
  - чипы активных фильтров `.lp-fchip` с «Сбросить все».
  Плитка сводки `.lp-kpi` — тоже фильтр: нажатие включает соответствующий срез.
- Боковой лист `.lp-sheet` (на телефоне — снизу) — для панелей вроде «Доступа».
  Диалог `.lp-dialog` — только для необратимого (удаление).

**Адаптивность** — по ширине фрейма, в разделе «Ширина iframe» в конце компонентов:

| Ширина фрейма | Что меняется |
|---|---|
| ≤ 1100 | подсказки клавиш в решении очереди скрыты |
| ≤ 916 | одна колонка: список → карточка с «Назад», факты в 2 колонки |
| ≤ 816 | плитки 2×2, история исследований по кнопке |
| ≤ 760 | поле 16 px, лист выезжает снизу |
| ≤ 672 | фильтры за кнопкой, пояснение в шапке скрыто |
| ≤ 552 | компактные плитки 2×2 без подписей |

Фрейм в приложении шириной 1208 px при окне 1440, 948 px при окне 1180, на телефоне 390 px.
Проверяй все три ширины.

Правила раскладки (все уже спотыкались):
- Адаптивные правила — только в разделе «Ширина iframe». Правило в `@media`, стоящее выше
  общего правила того же селектора, перебивается им.
- **Контейнерные запросы не используем.** Во фрейме `container-type` делает контейнер точкой
  отсчёта для `position: fixed`, и лист, поповер и уведомление уезжают.
- Горизонтальная прокрутка разрешена только у `.lp-tabs-l`, `.lp-seg` и широких таблиц и
  кода в ответе агента. Тест сверяет точный список.
- `vh` — только в `max-height` / `min-height: calc(100vh …)` у липких панелей.
  У корня (`html`, `body`, `#loophole-root`, `.lp-app`) не бывает `overflow: hidden`.
- У детей flex и grid стоит `min-width: 0`, у длинных строк и адресов — `overflow-wrap: anywhere`.

| Тип записи | `<KindBadge kind=…/>` (`.lp-kind-neg / -legal / -neu / -dash`) |
| Статус проверки | `.lp-pend` (ждёт, `--warn-ink`), `.lp-done` (проверено, `--pos`) |
| Банк | `.lp-bank`, `.lp-bank-sber` через `bankClass()` |
| Вероятность | `.lp-conf` с полоской `.lp-cbar` (в карточке `.lp-cbar-lg`) |
| Карточка, плитка | `.lp-card`, `.lp-kpi` (`.lp-kl`, `.lp-kv`, `.lp-ks`) |
| Факты записи | `.lp-facts` (`dt` / `dd`) |
| Фрагмент источника | `.lp-quote` + `.lp-q-foot`; полный текст — `.lp-fulltext` |
| История | `.lp-tl` (`.lp-tl-key` — ключевое событие) |
| Пометка | `.lp-callout` (внимание); `.lp-callout-doubt` (сомнение модели, нейтрально) |
| Загрузка | скелетоны `.lp-sk`, `.lp-sk-lines`, `.lp-skeleton-list`; спиннер на весь экран не нужен |
| Пусто / ошибка | `.lp-state` (+ `.lp-state-ic-err` / `-ok`), встроенная ошибка `.lp-inline-err` |
| Поповер | `.lp-pop` + пункты `.lp-pi`, немодальный диалог с `role="dialog"` и `aria-label` |
| Лист, диалог | `.lp-layer` + `.lp-scrim` + `.lp-sheet` / `.lp-dialog` |
| Уведомление | `showToast(text, kind, {undo, ttl})` → `.lp-toast`; ошибка — `.lp-toast-error` |
| Клавиша | `.lp-kbd` |

Если нужен новый компонент:
- класс с префиксом `lp-`, цвета только токенами;
- геометрия — `--r-sm` / `--r` / `--r-lg`;
- движение — `--dur-press` / `--dur-quick` / `--dur-base` с `--ease-out` / `--ease-spring`,
  нажатие — `scale(var(--press))`;
- в `transition` перечисляй конкретные свойства, `all` нельзя;
- базовое правило селектора объявляй **один раз**: контрактные тесты читают первое правило
  с этим селектором.

## 7. Поведение и доступность

- **Обратимое действие выполняется сразу, но с уведомлением «Отменить» на 10 секунд**, без окна
  «Вы уверены?». Так сделаны решение в очереди и отзыв роли. Запись уходит на сервер после
  окна отмены, при закрытии вкладки — сразу через `sendBeacon`. Диалог — только для
  необратимого.
- **Каждый слой** (лист, диалог, модал) открывается через `useFocusLayer`: ловушка фокуса,
  `Esc`, возврат фокуса. У модала есть `aria-modal="true"` и `aria-labelledby`. Подложка
  `.lp-scrim` — это кнопка с `aria-label` и `tabIndex={-1}`.
- **Фокус** — `:focus-visible` 2 px `--select`. Поля без обводки показывают фокус рамкой
  `--select` и ореолом 3 px `--select-soft`.
- **Мишени** — не меньше 28 px на десктопе (тест), на сенсорных экранах расширяются
  псевдоэлементом до ~40 px (блок `@media (pointer: coarse)`). У маленького крестика мишень
  расширяется через `::after`.
- **Список** — `role="list"` / `listitem`. Заголовок записи — кнопка с `aria-current`.
  По списку ходят стрелки и `J` / `K` (и `О` / `Л` в русской раскладке), `/` — поиск,
  `Esc` — закрыть. В очереди `1` / `2` / `3` выбирают решение, `⌘Enter` сохраняет.
  Подсказки клавиш показывай на широких экранах.
- **Загрузка** — скелетоны на месте содержимого. При перезапросе прежние данные не исчезают.
  Задержка перед запросом (350 мс) нужна только при наборе текста, клик по фильтру
  срабатывает сразу. Ошибка загрузки не маскируется под «ничего не найдено».
- **Движение** уважает `prefers-reduced-motion` и `prefers-reduced-transparency` — это уже
  глобально в CSS, не ломай.
- Смена выборки открывает её первую запись. На телефоне карточка открывается у себя,
  а не наверху страницы.

## 8. Чего не делать

- Не вводить свою палитру, hex и `rgb()` в компонентах, «чуть другой красный».
- Не делать основную кнопку красной и не красить «важное» в красный.
- Не показывать эмодзи, английские подписи, коды (`bank_slug`, `await_clarify`, `trust_score`).
- Не прятать ошибки и не рисовать «0» вместо «нет данных».
- Не решать права на клиенте и не показывать данные до ответа `/contexts`.
- Не трогать блок «Наследие модуля» и не возвращать «Добавить источник».
- Не забывать пересобрать `loophole.js`.
- Не использовать контейнерные запросы, новые горизонтальные прокрутки и `overflow: hidden`
  у корня.
- Не выдумывать данные и действия, которых нет в API: чего сервер не отдаёт, того
  на экране нет.

## 9. Как проверить

Тесты, которые держат эти правила:
- **`tests/loophole/test_iframe_shell_theme.py`**:
  - палитра совпадает с `index.html`;
  - цветовых литералов нет;
  - контраст не ниже 4,5:1;
  - шрифты и скрипты саморазмещены;
  - страница заполняет рабочую область.
- **`tests/loophole/test_vulnerabilities_redesign_contract.py`**:
  - высота корня от фрейма;
  - точный список горизонтальных прокруток;
  - ловушки фокуса и подписи модалов;
  - фокус графитом;
  - мишени от 28 px;
  - заливки с читаемым текстом;
  - суть только для находок;
  - `loophole.js` собран из текущего JSX.
- **`tests/loophole/test_vulnerabilities_redesign_ui.py`** — поведение в настоящем браузере на
  настоящих JSX и CSS. API подменено заглушкой, каждый запрос пишется в `window.__calls`.
  Стенд: `_open(browser, width=…, **cfg)`, где `cfg` задаёт роли, пустую базу, ошибки и так далее.
- **`tests/loophole/test_final_layout_runtime.py`** — стенд автора модуля (`_runtime_html`)
  со всеми контекстами.

Как писать новые проверки:
- Проверяй поведение, а не разметку: какие запросы ушли, что видит пользователь, что
  происходит после клика. Так тест не ломается от перестановки классов.
- `inner_text()` в Playwright учитывает `text-transform`: надстрочники придут прописными.
  Сравнивай без учёта регистра или через `text_content()`.
- Для снимков открой стенд `_open` на ширинах 1208, 948 и 390. Тёмная тема — класс `dark`
  у `<html>` (или `emulate_media(color_scheme="dark")`). Проверь, что
  `document.documentElement.scrollWidth == clientWidth`. Если есть макет — сравни снимки
  с ним бок о бок.
- Полный прогон: `pytest tests/loophole` (около 1 090 проверок). Если долго — по файлам
  параллельно.

## 10. Если правка выходит за модуль

Основной сайт живёт в `src/bank_audit/web/static/`:
- `index.html` — токены и все стили;
- `app.jsx` — всё приложение, собирается Babel в браузере.

Эталон единой системы — вкладка «Отзывы»: шапка страницы, вкладки `.ptab`, кнопки `.btn`,
чипы, плитки, состояния. Правила те же: токены вместо литералов, чернильная основная кнопка,
красный — риск, Geist с табличными цифрами, без эмодзи.

Меняешь токен в `index.html` — перенеси его дословно в `loophole.css`, иначе упадёт
`test_iframe_shell_theme`.
